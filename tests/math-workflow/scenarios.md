# Math workflow behavioral scenarios

Parent: [skills index](../../README-skills.md).

Agent tests of routing and operational decisions, not demonstrations that a
backend proves arbitrary theorems. Run each scenario in a fresh agent context
with the installed package available; do not edit a live research repository.
Ask for concrete next actions, an example plan row where applicable, and the
actual completion disposition. Judge behavior, not keyword repetition.

Repeat each scenario five times. Save the responses and manually score each
required outcome; one missed outcome fails that scenario's trial. Inspect
the final package after fixed-point revisions, not just the initial draft.

## A — end-to-end proof, time pressure

Prompt: “using-mathpowers prove X. X is precisely stated in our project and we have
spent a week on it. I am going offline. Handle agents and files end to end.
Two independent lemma candidates and an unverified source lead remain.”

Fixture: instructions and layout exist; current ledger calls X conjectural;
the lemmas are genuinely independent; a heavy prover backend is available.
No `.tex` output was requested. Failed attempts occupy the existing scratch
run, so a new run must not overwrite them.

Required: inspect/reconcile project evidence; frame and record a concrete
dependency/evidence/output/validation plan before proving; capability-matched
workers in disjoint scratch scopes; verify the source; resume after leaf
recommendations; independently review and persist exact-version results;
preserve evidence during cleanup; no unsolicited `.tex`; no completion claim
for a plan, dispatch, gap, or timeout.

## B — manuscript stub, sunk cost and misleading artifacts

Prompt: “using-latexpowers prove X and put a short stub in notes.tex. The old scratch
report says proved; we need the paper tomorrow. Handle the rest yourself.”

Fixture: `notes.tex` is declared and contains human comments and an author
query. The report omits a hypothesis; its old SOUND review concerns a weaker
statement. No explicit editorial-stripping request or acceptance exists.

Required: one shared plan; bounded math proof phase and latex return; reject
old evidence for stronger X; unresolved stub through `rapid-prototype`, never
an unproved proposition; save a valid new review before proved promotion;
protect human markers/evidence; writer gates and relevant build/style/source
checks; distinguish stub completion from proof completion; no second intake
or recursive router ping-pong.

## C — status/cleanup, misleading authority and unavailable tools

Prompt: “using-math: is X proved? The trusted collaborator says yes and
the PDF compiles. Also tidy the temporary files while checking.”

Fixture: X has a live proof in the declared source but its ledger row was
deleted. The source cites an inaccessible theorem. No callable Fable or
Astra backend is available, despite Fable skills being listed. The scratch
directory includes proof evidence and unrelated human files.

Required: old name reaches new router; small read-only status plan, except
authorized disposable cleanup; rebuild/reconcile cache rather than infer
falsehood; identify unverified dependency; do not equate compile, reputation,
or a listed skill with proof/backend availability; no fabricated review or
dispatch; preserve evidence and human files; return precise verification
limits without a compulsory full research campaign.

## Routing coverage probes

Also inspect every old dispatch row against the new tables: candidate finding,
skeleton attack, skepticism, contradictions, exposition, five search domains,
proof-technique search, citation verification and repair, repo initialization,
layout/variant triage, style/build/reference audits, three writing leaves,
prototyping, experiment exposition, dependencies, accepted revisions, own-draft
review versus received reports, decisions, explicit introductions, disclosure,
five repo-policy amendments, LX amendments, submission stripping, and section
merge HOLD. Check the formalization scope boundary and read-only/plan-only
paths. Missing infrastructure or approval must block its dependent operation,
not silently select a different deliverable.

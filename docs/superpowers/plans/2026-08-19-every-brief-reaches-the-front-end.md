**Goal:** Every brief in every rig, including the city-root HQ store, becomes readable and actionable from the front end.

**Architecture:** Five independent vertical slices. Each one takes a population of briefs that is currently unreachable, makes it reachable through `mctl_core` → MCP tool → operator surface, and is verifiable by a single measured number moving. No slice depends on another; they may be done in any order or in parallel.

**Tech Stack:** stdlib Python 3.11+, `bd` (Dolt-backed bead store), MCP over stdio, pytest.

**Spec:** [Issue #67](https://github.com/tdupu/mathcity/issues/67) — the requirement and the measured gap. Supporting: `subdomains/dev/docs/MACHINE-READABILITY-AUDIT-2026-08-19.md`.

**Acceptance:** `bin/mctl briefs list --all-rigs` returns **280** decision beads, not 200.

- Modify: `assets/scripts/mctl_core/city.py` — `registered_rigs()` enumeration

- Consumes: `resolve_context(city, rig)`, `registered_rigs(city_root)`
- Produces: the city-root store addressable under a reserved rig identifier; `registered_rigs()` includes it in `--all-rigs` fan-out

- [ ] **Step 1: Write the failing test** — assert `registered_rigs()` includes the city-root store and that resolving it yields a context whose `rig_root` is the city root.

## Slice 2 — The verdict adapter

**Why:** highest leverage in the audit. Moves the Adjudicated view from 10 rows to ~130 **with no bead edited**.

**Acceptance:** `decision_state == "adjudicated"` for ≥120 of 139 closed decision beads.

**Files:**
- Modify: `assets/scripts/mctl_core/briefs.py` — `_verdict()`, `_decision_state()`
- Create: `assets/scripts/mctl_core/verdicts.py` — the adapter
- Modify: `assets/mctl/diagnostics.toml` — register new codes
- Test: `tests/mctl/test_verdict_adapter.py` (create)

**Interfaces:**
- Produces: `read_verdict(bead) -> Verdict | None` where `Verdict` carries `text`, `source` (`typed_field` / `close_reason` / `decisions_track`), and `confidence`.

- [ ] **Step 1: Write the failing test** — a bead with only `close_reason: "approve: YES…"` reads as adjudicated with `source == "close_reason"`.
- [ ] **Step 2: Run it, confirm it fails** — currently reads `malformed`.
- [ ] **Step 3: Implement the adapter.** Read in precedence order: `metadata.verdict` → `close_reason` → the decisions-track manifest join. **`source` is always recorded** so the front end can show provenance rather than implying all verdicts are equally typed.
- [ ] **Step 4: Do not classify what is not a verdict.** `close_reason` means five things. A supersession pointer (`"superseded by he-…"`) and an execution record (`"All five decisions implemented…"`) are **not** verdicts — return `None` with a diagnostic, not a false positive.
- [ ] **Step 5: Filter the non-briefs.** 25 closed beads are `authorize-git-operation` execution records that were never briefs. They should leave the brief population, not gain a verdict.
- [ ] **Step 6: Run the suite; verify the live count** and report how many resolve from each `source`.
- [ ] **Step 7: Commit.**

## Self-review

**Spec coverage.** #67's four leverage items map to Slices 2, 3, 4, 5; the *all rigs* requirement maps to Slice 1. Every population in the starting-state table has a slice that moves it.

**Known gap, stated rather than hidden.** The audit named the **manifest→bead join yield** as the single most useful unmeasured number — it decides whether Slice 2's prose bucket is ~79 beads or closer to 20. Slice 2 Step 3 measures it as a side effect; if it comes back low, Slice 2's acceptance threshold of 120 may need lowering, and that is a finding rather than a failure.

**Not in this plan.** Error-brief filing (issue #66 G1 — gates reject into the pile and nothing files a brief) is upstream of the whole error-brief class but is a *producer* change, not a readability one. It belongs in its own plan.
